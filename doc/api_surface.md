# HTTP API surface

Scout ships transport-neutral services and thin HTTP bridges over them. Every handler authenticates through keel, derives the tenant and the acting person from the session, calls one service method, and serializes the result. Tenant and actor identity never come from request JSON; services authorize every call themselves, so a product service calling them directly is held to the same grants as a person.

The compile-time DTOs live in `api/`. Agent Studio's compatibility profile is `studio-v2`: stable route names and snake-case fields, independent of the Scout domain.

### Authorization

Actions are on the `AGENT_STUDIO` authorization object, checked in the service at the value `agent:<agent_id>`; `CREATE` is checked at `agent_type:<type_id>` because the agent has no id yet, and a copy also needs `VIEW` on its source. keel matches a grant's `low_limit` exactly or as `*`, so a role holds every agent of its tenant (`*`) or named agents. A group of agents is expanded to explicit grants. `ListAgents` returns only the agents the actor may view; direct access to any other fails closed. `StudioService.Principals` and `Roles` are required.

`domain.StudioActor` carries the tenant and a `domain.PrincipalRef`: a person (`human`, the decimal `user_account.id`) or a service such as a product installer (`service`, an agent principal registered for it). `agent_studio_event` records the principal's kind and id; the user-only columns `modified_by`, `published_by`, and `bound_by` take the person and stay empty for a service.

Scout seeds `AGENT_STUDIO` with `VIEW`, `CREATE`, `EDIT`, `TEST`, `PUBLISH`, `RESTORE`, `ARCHIVE`, `APPROVE_PUBLISH` (a publish or restore review), `TEMPLATE`, `TEMPLATE_PUBLISH`, `REVIEW` (production turns under review), and `OVERRIDE_GATE` (publish past an evaluation gate); `AGENT_ADMIN` holds all of them but `TEMPLATE_PUBLISH` and `OVERRIDE_GATE`, and `AGENT_OPER` holds `VIEW`, each at `*`. `TEMPLATE` is checked at `agent_type:<type_id>`; `TEMPLATE_PUBLISH`, which like `OVERRIDE_GATE` no seeded role holds, at `template_audience:all` or `template_audience:tenants`. Restriction layers are tenant-wide and use their own object, `AGENT_RESTRICTION`, with `VIEW` and `REPLACE_TENANT` checked at the value `tenant`; `AGENT_ADMIN` holds both at `*`. Applications assign roles and narrower grants.

### Field mappings

| HTTP field | Scout domain field | Persistence source |
|---|---|---|
| `agent_name` | `AgentID` | `agent_profile.agent_id` |
| `agent_type` | `AgentTypeID` | `agent_profile.agent_type_id` |
| `prompt_header_id` | `PromptSectionID` | `prompt_section.id` |
| `agent_revision` / `expected_agent_revision` | draft revision | `agent_draft.draft_revision` |
| `type_defaults_revision` / `expected_type_defaults_revision` | prompt profile revision | `agent_alias.revision` |
| `published_version` / `version` | immutable version | `agent_version.agent_version` |
| `is_default` | alias target equality | `agent_alias.agent_id` |
| `archived` | archived state | `agent_profile.state_code = 'X'` |
| `active` | stable deployment equality | `agent_deployment.stable_version` |
| `enabled` | operational and release-enabled value | `agent_profile.state_code`, `agent_draft.enabled` |

`studio-v2` represents versions as JSON numbers. Restore and release-section requests require positive decimal versions, and release and history responses reject a stored non-decimal version. Summary and drift responses use zero when an internal version is not decimal. Scout treats versions as opaque strings internally.

Model fields use identifiers under `models`: `text_model`, `image_model`, and `video_model`. `StudioService` resolves each to a `(provider_id, model_id)` pair and fails on zero or several matches.

Each prompt section carries `layers`, widest scope first, with `effective_text` and `effective_output`:

| Layer field | Meaning |
|---|---|
| `scope_id`, `scope_kind` | the contributing scope; the first layer is the selected platform baseline, `scope_kind` `platform`, `scope_id` its baseline key |
| `merge_mode` | `A` (append, the default for a layer Studio writes) or `R` (replace) |
| `sealed` | set by the layer's own scope; no narrower layer may follow it |
| `editable` | response only: true for the agent's scope and its type's tenant-default scope |
| `instruction`, `output` | the layer's own text, not the merged text |
| `bound_by` | response only: the user who last edited the layer; absent on the baseline |

A draft response names the two scopes a layer may be added at, `agent_scope_id` and `type_scope_id`. A save writes the editable layers it is sent and ends an editable binding it is not sent, so a client returns the layers it did not change. Layers that are not editable are ignored on the way in. Release sections carry `source`: the `scope_id`, `scope_kind`, `merge_mode`, and `sealed` of the layer that decided the section when the release was compiled.

### Mutation contracts

- `Create {agent_type, display_name, copy_from?, template_id?, template_version?, references?, idempotency_key}` makes a disabled agent in state `D` (draft) with no release. Its settings are a copy of `copy_from` — models, extension, and every binding in force at the source agent's scope — or of a template version, or else the type's tenant defaults. It refuses a type the tenant or the product catalog does not offer, a display name another agent of the type has, and a type already holding `agent_studio_max_agents_per_type` agents. The type row is locked for the transaction. `agent_create_request` keys the idempotency record by tenant, principal, and key: a replay returns the agent it created, and the same key with another request is a conflict. `template_id` takes a template the tenant may use, at `template_version` or, when 0 or absent, its newest usable version; `references` maps each of the template's knowledge, entitlement, and approver slots to a value of the tenant (`{"knowledge": {slot: id}, "entitlement": {slot: id}, "approval_routing": {slot: "role:<ref>"}}`), and every slot must be mapped. The template pins the type version, and the agent records the template version it derives from. Without `StudioService.Templates` composed `template_id` is refused, and `template_version` or `references` without `template_id` always are.
- `SaveDraft` checks the agent and prompt-profile revisions, updates the agent configuration and prompt bindings, advances the draft revision and any changed prompt-profile revision, records the actor, and returns a fresh draft. `enabled` updates both the operational switch and the prospective release value.
- `SetEnabled` is the kill switch: it updates operational and prospective release state behind the draft revision only, and records its optional `reason`. A disabled agent admits no new turn opened through the data plane's turn record store: it reads the agent's state under a share lock in the transaction that opens a turn, so no turn opens after the switch commits. A product that opens turns through `TurnLedger` checks the state itself.
- `Rename` changes `display_name` behind the draft revision; the agent id is permanent because grants and evidence key on it.
- `Archive` withdraws an agent; its releases, audit, and conversations remain. It refuses the type's default, an agent named by a delegation grant that has not ended (when `StudioService.Delegations` is set), and whatever a product validator refuses in phase `archive`, such as a schedule. An archived agent admits no turn and is read-only. `Unarchive` returns it disabled.
- `TestDraft` executes the current saved draft; it does not test unsaved content or publish a version. The draft's own `max_duration_seconds` bounds the model call; a call it stops is still charged and answers `422`.
- `Publish` checks both revisions, compiles every language, writes one immutable `agent_version`, and deploys it: as the stable release, or with `canary_percentage` between 1 and 99 as a canary beside the current stable one; 0 or 100 deploys it stable. An agent's first release cannot be a canary. With `effective_at` (RFC 3339) in the future, at most 366 days ahead, the version is written and frozen but not deployed: the response has `active: false` and an `activation`, and the activation worker deploys it later (see `activation` below). An agent holds at most one pending activation.
- `Restore` copies an immutable source version and its frozen settings into a new stable version and records `restored_from_version`; it never mutates history. A version without frozen settings cannot serve a turn and is refused (`409`). Where the tenant's separation reviews restores, a restore needs an approved restore review of that version (see `publish-review`).
- `Reset` ends prompt bindings only: `agent_override` those of the agent's scope, `type_default` those of its type's scope, `platform_baseline` both; optionally narrowed to one section, one language, or both.
- `SetDefault` moves the type alias with optimistic revision checking; an agent without a deployment remains unpublished.

`GET settings?agent_name=` returns the non-prompt bindings on the scope chain and each effective value with its winning and superseded sources. `POST setting` writes or removes one binding at the returned agent or type scope behind the matching revision, compiles the whole chain before writing, and refuses widening or sealed overrides. Set, budget, autonomy, limits, approval-routing, evaluation-gate, and health-alerts kinds use the kind name as `resource_id`; policy may use several ids. A `limits` value is `{turns_per_minute, max_steps, max_tool_calls, max_duration_seconds}`, 0 meaning not limited at that scope; a narrower scope may lower a field but not raise or unset it.

A `budget` value is `{tokens, cost_minor_units, currency?, exponent?, period, window_seconds?, timezone?}`. `period` is `turn`, `rolling` (with `window_seconds`, 60 to 31,622,400), or `day` or `month` (with an IANA `timezone` of at most 64 characters, not `Local`); a field the period does not take is refused. Ceilings run from 0 (not limited) to 10^18 and a value caps at least one; removing the binding removes the budget. A cost ceiling names an upper-case three-letter `currency` and its `exponent` (0 to 6), which must match the currency catalog (`400` on field `value`); a value without a cost ceiling takes neither. A narrower budget keeps the inherited period, window, timezone, and, when both cap cost, currency and exponent, and may only lower a ceiling (`403`). A value without `period` is refused.

An `approval_routing` value is `{routes: [{id, match: {tools?, sources?, min_risk_tier?}, approver: {kind, ref}, deadline_seconds, escalation?: [{approver?, extension_seconds}], on_exhausted?}]}`. `kind` is `role` or `position`, an opaque product reference of at most 128 characters; `sources` are `autonomy`, `policy`, and `guardrail`; `tools` are up to 16 exact ids or prefixes ending in one `*`. A deadline and each extension run from 60 seconds to 30 days and a whole route at most 90 days; a route takes at most 3 escalation steps, and a step without an approver extends the deadline under the current one. `on_exhausted` is `expire` (the default) or `hold`. Order is precedence, the first matching route wins, and a route an earlier one covers is refused as unreachable. A binding holds at most 32 routes and an agent's effective routing 64. A narrower scope overlays its parent route by route; it keeps every inherited route's id, order, match, approver, and step approvers, and may only shorten deadlines and extensions or change `hold` to `expire`.

An `evaluation_gate` value is `{metric, min_score_bp, max_regression_bp?, min_samples, required_scopes}`: `metric` is the score name (1 to 64 characters), `min_score_bp` and `max_regression_bp` run from 0 to 10,000 basis points of a 0..1 score, `min_samples` from 0 to 1,000,000, and `required_scopes` names `dev`, `gate`, or both. It binds with merge mode `R` (replace) only. A narrower scope keeps the inherited metric and every required scope and may only raise the minimum score or samples or lower the regression bound (`403`). Removing or loosening the gate in force at a scope, through `setting` or an `import` that replaces the agent's bindings, needs `OVERRIDE_GATE` (`403`) and `StudioService.Audit` (`503` without it), and is recorded as Studio event `GATE_LOOSEN` and an audit decision. The gate decides whether a draft may be published; no release freezes it.

A `health_alerts` value is `{window_minutes, min_turns, max_failure_rate_bp, max_p95_latency_ms, max_hard_safety_events, max_silence_minutes, max_unresolved_minutes}`, every field an integer with 0 meaning not evaluated: `window_minutes`, `max_silence_minutes`, and `max_unresolved_minutes` run from 0 to 10,080, `max_failure_rate_bp` to 10,000, `max_p95_latency_ms` to 86,400,000, and `min_turns` and `max_hard_safety_events` to 1,000,000. It binds with merge mode `R` (replace) only. A narrower scope keeps a window its parent sets and may only lower a threshold, the sample floor, the silence span, or the unresolved-outcome span its parent sets, never raise or unset one (`403`). No release freezes it.

Publishing stores a canonical JSON definition containing models, compiled prompts, effective settings, tool and skill versions from the type narrowed by their bindings, named product sections, and extension data. Runtime reads only immutable definitions. A product extends publication through `StudioService.Guards` (`contract.PublishGuard`, which may refuse a publish or restore), `Sections` (`contract.DefinitionSection`, a named part frozen into `AgentDefinition.Sections` and its digest), and `ReleaseWriters` (writes in the release transaction). The optional features that shape a release are composed there too: `StudioGuardrails` as a section and a release writer, `StudioGovernance` as a section and a guard, `StudioPublishReviews` as a guard and a release writer for publishes and restores, `StudioApprovalRouting` as a guard, and `StudioEvaluationGate` as a guard that decides again inside the publish or restore transaction. A release with a cost budget needs `StudioService.Pricer` (`contract.ModelPricer`): publish, restore, and scheduled activation refuse a currency missing from the catalog, a frozen exponent the catalog no longer has, and a selected model that is unpriced or priced in another currency.

### Optional features

- `canary`, `promote`, and `rollback` change which release new conversations take, through `contract.AgentVersionTrafficManager`; a live conversation keeps its release. Each records a Studio event. `StudioTraffic.Separation` is required: where it reviews restores, `canary` only re-weights the current canary, `promote` takes only the current canary or stable version, and `rollback` only ends a canary; any move that returns another version to service is `409` and takes a reviewed restore.
- `explain?conversation_id=` returns the release a conversation runs on, the rule that chose it (`stable`, `canary`, `experiment_cohort`, `pilot`, `compliance_pin`, `tenant_pin`, or `request_pin`), the alias it was requested through, a pin's reason, and the definition digest.
- `pilot` serves one published, unquarantined release to named people and positions; it decides only the release a new conversation of that person starts on, after compliance and tenant pins and before cohorts and canaries. `subject_kind` is `P` (principal, a canonical decimal user id) or `O` (position, the product's opaque reference, matched through `contract.PositionResolver`). A subject pilots one version of an agent at a time, re-adding an open membership returns it unchanged, `remove` ends it, and an agent holds at most `agent_pilot_max_members` open memberships.
- `activations` lists an agent's 100 most recent scheduled publishes, latest `effective_at` first, each `P` (pending), `A` (activated), `R` (refused) with a `reason` code (`VM` version missing, `DM` digest mismatch, `NA` not authorized, `AA` agent archived, `GR` guard refused, `DC` deployment changed, `AE` attempts exhausted), or `X` (cancelled). `activation/cancel` withdraws a pending one. The activation worker (`controlplane.NewReleaseActivationWorker`, run from a product worker binary) re-checks the scheduler's `PUBLISH` authority, the definition and settings digests, every publish guard, and that the deployment has not moved since scheduling, then swaps it.
- `delegate {agent_name, grantee, action_scope, max_depth, budget_minor_units?, currency?, approval_required, valid_from?, valid_to}` lets `agent_name` hand work within `action_scope` to another agent of the tenant; its author needs `EDIT` on the grantor and `VIEW` on the grantee. A grant must end in the future, its depth is at most `agent_max_delegation_hops`, a budget names its currency, and it is refused when the grantee already delegates, directly or through others, back to the grantor. At use, `principal.GrantAuthorizer` still checks that the grantor holds what the grant conveys. `undelegate` ends one of the agent's own grants.
- `pause` disables the agent with a reason and then applies its policy to live turns: `finish` lets them complete, `cancel` asks each to stop through the durable turn canceller, and `suspend` holds each queued or parked turn at once and asks each running one to hold at its next durable checkpoint. It returns the new revision and the counts `cancelled`, `held` (held at once), and `hold_requested` (asked to hold). Unpausing releases no held turn; `turn/release` does, one at a time. A deployment without turn control refuses `suspend` (`503`).
- `turn_control` operates an agent's live turns; every route also needs `VIEW` on `AGENT_STUDIO`, and an agent the caller may not view, or a turn of another agent, is `404`. A turn is `{request_id, conversation_id, turn_no, status, fence, hold_code?, hold_requested, hold_reason?, cancel_requested, queued_at, started_at?, held_at?}`: `status` is a turn status code, `Q` (queued), `R` (running), `S` (streaming), `U` (suspended), or `H` (held), and `hold_code` is `C` (held at a checkpoint on request), `A` (held because its agent was suspended), `P` (preempted by an operator), or `U` (held on a call whose outcome is unknown). `turn` also returns `outcomes`, the turn's non-read-only calls oldest dispatch first, each `{execution_step_id, call_id, tool_id, tool_version, status, dispatch_fence, dispatched_at, deadline_at, deadline_passed, resolution?, resolved_fence?, resolver_kind?, resolver_id?, resolved_at?, note?, evidence?}`: `status` is `I` (in flight), `A` (accepted, awaiting its lookup), `C` (completed), `F` (failed), or `U` (unknown); `resolution` is `G` (gateway), `W` (late worker report), `E` (effect observation), `L` (outcome lookup), `T` (attestation), or `M` (MCP confirmation); `deadline_passed` says a person may attest an open call now; `evidence` is `{uri, digest}`. `turns/live` pages the non-terminal turns newest first by queue time, `limit` up to `agent_live_turn_max_page_size` (default `agent_live_turn_page_size`), continued by the previous page's `next_before`; a larger `limit` or a malformed cursor is `400`. `turn/hold` takes `mode` `checkpoint` or `preempt` and a non-blank `reason`: a queued or suspended turn is held at once; in `checkpoint` mode a running one is asked to hold at its next durable checkpoint, and the first reason stands; in `preempt` mode, which also needs `PREEMPT`, a running one is held at once and its worker fenced out. It returns `{held, status, fence}`. An ended or cancelled turn is `404`. `turn/release` names the `fence` the held turn showed, re-admits its budget (a refusal, including a reservation already settled, leaves it held), and returns it to the queue under a new fence; a turn that is not held at that fence, or that has a call whose outcome is `I`, `A`, or `U`, is `409`. `turn/outcome/lookup` and `turn/outcome/attest` act on one call of a turn that is held or ended at the stated `fence` (otherwise `409`; an unknown call `404`). A lookup asks the effect verifier or the composed outcome lookup without sending the call and returns the call's outcome, settled when the answer was definite and unchanged otherwise; without a composed reconciler it is `503`. An attestation needs `outcome` `completed` or `failed` (another word is `400`), a `note` of 1 to 500 characters, and optional `evidence` `{uri, digest}` with a SHA-256 digest that the composed evidence verifier accepts; it is `409` before the call's deadline (`deadline_passed`) or when it conflicts with an earlier attestation, `403` when the separation policy refuses the person, `400` for evidence the verifier refuses, and `503` when no separation policy is composed or it cannot be evaluated, and for evidence without a verifier. It returns `{outcome, awaits_second}`: `awaits_second` means the call needs a second authorized person to attest the same outcome before it settles. An identical repeat returns the same result. A worker that holds its turn on an unknown outcome ends the stream on a `held` frame, as a checkpoint hold does; a call that definitely failed reaches the model as its bounded error class, which includes `not_sent`, `no_effect`, and `output_withheld` (it took effect but its output cannot be shown) when no more specific class applies; an unknown outcome reaches the model not at all and holds the turn under the class `outcome_unknown`.
- `feedback` counts the ratings, 1 to 5, each release received in a window of at most 92 days. It never reports a person.
- `runs` pages the agent's settled runs, newest first: release, task kind, request, status, and completion time.
- `runs/trace` returns one settled run with its turn's status and timing and its `events`, each `{sequence, kind, at}` plus the member named by `kind`: `model_step` (journal location and digest, models, usage, `finish` `answer` or `tool_calls`), `tool_call` (tool, `outcome` `ok` or `error`, the bounded `error_class`, observed `effect`), `guardrail`, `approval` (the request, its verdict, and the `proposed_digest` it binds to), or `decision` (`source` `audit`, or `charter` with the disposition Charter recorded). A trace carries names, codes, timing, usage, and digests, never model output, tool arguments, or tool results. Events order by time, then by source (journal, guardrail, approval, audit, Charter), then within a source; the sources are stamped by different clocks, so cross-source order near one instant is approximate. A run without a request id has no events. Reading stops at `agent_run_trace_max_events` events or the loop journal bounds, and the trace then holds only the consistent prefix before the first unread entry and reports `truncated`. A missing `agent_name` or a non-positive `run_id` is `400`; a run of another tenant or agent, or of an agent the caller may not view, is `404`; a deployment without run traces is `503`; a source that is rate-limited or not ready is `429` or `503` without its detail; a journal object that fails its digest or does not decode is a sanitized `500`.
- `usage` returns lines of settled usage per release, model (`provider`, `model`), person, product work reference, and currency, with the currency's exponent: turns, input and output tokens, tool calls, and cost in minor units. Usage no model performed, such as tool calls, is on a line without a model. `turns` counts the turns whose work the line holds, so a turn that used two models counts on both lines and turns do not add up across models. A window spans at most 92 days and a report at most 1000 lines; a larger one is refused.
- `limits` reports the stable release's frozen execution limits, the agent's turns opened in the last minute, and its budget `{tokens, cost_minor_units, currency?, exponent?, period, source, window_seconds, timezone?, problem?}` when the release binds one or the composition sets a fallback. `source` is `release` or `fallback`; `window_seconds` is set for a rolling budget only. `problem` names why the budget cannot be enforced — `invalid_period`, `no_currency`, `unknown_currency`, `exponent_changed`, `currency_mismatch`, or `no_cost_quote` — and the agent's turns then fail closed. `spend` `{period_start, period_end, tokens, cost_minor_units, held_tokens, held_cost_minor_units, currency, exponent}` covers the current period `[period_start, period_end)` by the database clock, settled usage and live holds apart; a rolling period ends at the database's now. It is absent for a per-turn budget and when `problem` is set. `StudioLimits.Spend` is required (the data plane's `isolation.BudgetLedger`).
- `guardrails` shows the rules an agent inherits, widest first (`B` baseline, `P` platform, `T` tenant, `Y` type), and its own rules; a save replaces the own rules as a whole, behind the draft revision. An own rule may add a rule or tighten an inherited rule of the same id, never loosen it (`403`); `problem` reports own rules that no longer fit after an inherited layer changed. Publication freezes the rule set as section `guardrails` and pins it as the release's guardrail version. `safety-events` pages the agent's guardrail hits newest first, `limit` 1 to 500 (default 50) and `before` the last id seen; events carry rule ids and attribution, never inspected content.
- `restrictions` shows the platform restriction layer, read-only, and the tenant's, which `POST` replaces as a whole when it is still at `expected_digest` (empty before the first write; a stale digest is `409`). With `agent_name`, `overrides` lists the restrictions that take away tools or policy allow statements from the settings the agent's next publish would freeze, marking a denial with conditions `conditional`; `settings_problem` says why they cannot be computed. A layer holds at most 256 denials and 256 guardrail rules by default.
- `governance` edits the governance fields of the agent's Charter `AgentDefinition`, in Charter's member names, plus `triggerChannels` (`[{trigger, channel, binding?}]`, channel `conversation`, `mcp`, `api`, `schedule`, or `event`; Charter's `triggers` derives from them). `governance` is what a publish would freeze now and `draft` what Studio keeps; fields an enterprise `contract.GovernanceSource` supplies are read-only and refused on save; `charter.GovernanceSource` supplies them from the single Charter AgentDefinition in force for the agent's identity in the tenant's namespace. A schedule or event trigger needs a binding the product's `contract.TriggerBindingVerifier` proves, on save and on every publish. `problems` lists what a publish would refuse now; publication freezes section `governance`, and the flag `agent_governance_required_fields` names the fields a release must carry.
- `cases` shows and edits the agent's golden set: `op` `associate` (`golden_set_id`, `name`), `put` (`case`), or `remove` (`case_id`), the last two behind `expected_revision`; hidden gate cases are only counted. `cases/freeze` snapshots every case into an immutable set version. `evaluate` queues a run of one frozen set version against `subject` `{draft: true}` (frozen as a publish would, not persisted) or `{release}`; an agent holds at most `agent_evaluation_max_open_runs` open runs (`429`). `evaluation?run_id=` returns the run, its cost in minor units, and one page of results, `limit` up to 200 (default 50), continued by `next_before`; a run of an agent the caller may not view is `404`. A result's `cost` is the subject's spend and `evaluator_cost` what model-based evaluators spent scoring it; the run's `cost` is both together. When the product composes a rubric judge (`AgentEvaluationWorker.Judge`, `evaluation.GatewayRubricJudge`), each result graded against a rubric carries the scores `rubric_score` (0 to 1) and `rubric_pass` (1 or 0) from evaluator kind `rubric_judge`; a hidden gate case's rationale omits the model's text. The subject's frozen limits bound every case. The evaluation worker runs from a product worker binary. A case promoted from production review carries `review_item_id`; its `input` is omitted and `input_withheld` set for a reader without `REVIEW` on that turn's agent. A case may script `turns`, the inputs of turns 2..n, each non-blank UTF-8 of at most `agent_evaluation_case_max_bytes`, and `tools` `[{tool_id, output?, is_error?}]`, the sandboxed response to every call of one tool: JSON `output` of at most `agent_evaluation_case_tool_max_bytes`, or `is_error` with no output. A case holds at most `agent_evaluation_case_max_turns` turns, its input included, and `agent_evaluation_case_max_tools` tool responses, a `tool_id` (1 to 80 bytes) appears once, and anything else is `400`. A result carries `has_trajectory` when its trajectory is stored; `evaluation/trajectory` returns it as `{run_id, case_id, arm, events}`, each event `{sequence, kind, name?, payload?, offset_ms, failed?, recovered?, usage?}` with `kind` `token`, `tool_call`, `observation`, `state`, or `policy` and a `state` event named `turn` where each turn after the first starts. `arm` is `b` (the default) or, for a comparison, `a`; a gate case, a result without a trajectory, or arm `a` of a single-subject run is `404`, and a trajectory over `agent_evaluation_trajectory_max_bytes` is `400`; the route needs `StudioEvaluation.Outputs` (`503`).
- `compare` queues a comparison of two arms on the dev cases of one frozen set version: `a` is the reference and `b` the challenger, each exactly one of `{draft: true, model?}` (the draft frozen as a publish would, on its own text model or the `model` named), `{release}`, or, for `a` only, `{baseline_id}`, a recorded human baseline of that version. An arm of another kind, a `model` on a non-draft arm, or two arms with the same definition is `400`; an unknown release or a baseline of another version is `404`. A comparison is an evaluation run, counted against `agent_evaluation_max_open_runs` (`429`); the worker needs `AgentEvaluationWorker.PairJudge` (`evaluation.GatewayJudge`, which calls the judge route strictly through `SO` (structured output) as the requester), or the run fails. Each case's `verdict` is `A` (arm a), `B` (arm b), or `T` (tie); an arm that ended in a failed state loses without asking the judge, and a case whose judging failed has no verdict and a `reason`. Both arms' spend and the judge's count against `agent_evaluation_max_run_cost` and are settled even when an arm or storage fails. `GET compare` returns the run with both pinned arms (`subject` `D` draft, `R` release, or `B` baseline, a draft's `provider` and `model`, `definition_digest`), the `tally` (`a`, `b`, `tie`, `failed`), one page of `cases` in descending case id with both answers, their digests, scores, latency, and cost, and, when one arm is the draft and the other a release, `diff`: the changed `models`, `prompt_sections`, and `settings`. Stored answers on a page are capped at `agent_evaluation_compare_page_bytes`; an answer past the cap is left out with `output_omitted`. `limit` is as for `evaluation`; a run that is not a comparison is `404`, and the page needs `StudioEvaluation.Outputs` (`503`). `baseline` records one human output, 1 to `agent_evaluation_baseline_max_bytes` bytes of UTF-8, for every dev case of the version; `name` (1 to 200 characters) is unique in the version (`409`), and a version holds at most `agent_evaluation_max_baselines` (`400`). `baselines` lists them newest first. Both need `StudioEvaluation.BaselineStore`.
- `gate` reports the evaluation gate of the agent's current draft: the effective `policy` (absent when no gate applies), its `policy_digest`, `current_digest`, the `active_version` and the newest frozen golden set version a decision is compared with, the `decision` recorded for the digest, `stale`, `admitted`, and `problem` when the draft does not freeze. `gate/evaluate` decides the gate from stored results and records it, `409` when no gate applies: for each required scope, the newest completed single-arm run of the digest on the newest frozen version (comparison runs never count) must have no critical failure, at least `min_samples` results (at least 1), and a mean `metric` of at least `min_score_bp`, a result the metric did not score counting 0; with `max_regression_bp` and an active release, the release's newest completed run on the same version and scope must exist and score no more than that above the draft. A run holding more than `agent_evaluation_gate_max_results` results is `400`. Studio queues dev runs only, so a gate requiring `gate` needs runs the product queues. The `decision` has `verdict` `P` (pass), `F` (fail, with `reason`), or `O` (override), the `policy` applied, `base_version`, the set version, and `runs` (`run_id`, `role` `C` (candidate) or `B` (baseline), `scope`, `score_bp`, `samples`, `critical_failures`). Unchanged inputs replay the recorded decision, and a failing evaluation leaves a current override in place. A decision is `stale` once the effective gate changes (`policy_changed`), another release becomes active (`active_release_changed`), or, for a pass, a newer set version is frozen (`set_version_superseded`). `gate/override` admits the current draft's digest with a `reason` of 1 to 400 bytes; it is `409` when the digest is not the current draft's, the agent has no gate, or the gate already admits it, and `503` without `StudioEvaluationGate.Audit`, and is recorded as a Studio event and an audit decision.
- Where a gate applies, `publish` is refused (`409`, gate refusal `missing`, `failed`, or `stale`) unless the draft's digest has a current pass or override. `restore` needs a recorded pass or override for the restored version's digest, however stale, or `OVERRIDE_GATE`, recorded as Studio event `GATE_RESTORE_OVERRIDE` and an audit decision. A scheduled activation was admitted when it was scheduled. A publish or restore of an agent bound to a gate when no `StudioEvaluationGate` is composed is `503`.
- `reviews` pages an agent's production turns under human review, newest first by `item_id`: `status` `P` (pending), `G` (graded), `D` (dismissed), or `M` (promoted), `source` `S` (sampled: chosen by the production sampler when the turn completed) or `F` (feedback: rated at or below `agent_review_feedback_threshold`), and `release`, with `limit` up to `agent_review_max_page_size` (default `agent_review_page_size`) and `before` the last item id seen. Only completed turns of tenants whose sampling policy admits them are queued, one item per turn and at most `agent_review_max_pending` pending per agent; items hold references, never content, and never name who rated a turn. `review/turn` returns the item with its turn's `input` and `response`, each checked against its digest and at most `agent_review_max_turn_bytes` (`400`). `review/grade` records a `score` of 1 to 5, a `verdict` `P` (pass) or `F` (fail), `notes` (at most 2,000 characters), and the `expected_behavior` a promoted case keeps; `review/dismiss` resolves an item without a grade. Each resolves a pending item once: the same request again replays, any other is `409`. `review/promote` copies a graded item into the agent's golden set as dev case `review-<item_id>` behind `expected_revision`, with the turn's input and the grade's expected behavior, and returns the item and the set; a replay writes nothing, and a case of that id from elsewhere is `409`. An item of an agent the caller may not view is `404`.
- `health` reports an agent's production health over its `health_alerts` window, read from exact turn and safety event records: `window_minutes`, `measured_at`, `turns_by_status` (by turn status code), `samples` (completed plus failed turns, the failure rate's denominator), `insufficient_samples` when `samples` is below the policy's `min_turns`, `failure_rate_bp`, `duration_p50_ms`, `duration_p95_ms`, `first_response_p50_ms`, and `first_response_p95_ms` from queueing over completed turns (null without a sample), `last_completed_at`, `last_failed_at`, `safety_events` by severity, `open_alerts`, `open_outcomes` (the in-flight, accepted, and unknown tool calls of the agent's turns, whenever queued), the effective `policy` (null when none is bound) or `policy_problem`, `last_evaluated_at`, and `telemetry`: `stale` when the health evaluator owes the agent an evaluation it has not made within `agent_health_stale_periods` periods, else `missing` when the window holds no turn, else `fresh`. `alerts` pages the agent's alerts newest first by `id`, `status` `O` (open) or `R` (resolved), `limit` up to `agent_alert_max_page_size` (default `agent_alert_page_size`), and `before` the `next_before` of the previous page. An alert is `{id, kind, status, opened_at, resolved_at?, observed, threshold, window_minutes}`, `kind` `F` (failure rate, basis points), `L` (p95 latency, milliseconds), `H` (hard safety events), `S` (silence: turns in the span and its minutes), or `U` (unresolved outcome: turns held at least `max_unresolved_minutes` with an open call outcome, and the span's minutes). An agent the caller may not view is `404`. The health worker (`dataplane.NewAgentHealthWorker`) runs from a product worker binary.
- `publish-review` asks a second person to approve the exact release the draft would freeze. A review's authors are its requester, the last editors of every resource it adds or changes, and everyone who changed the draft since the last publish (`diff.editors`); none may approve it. Where `contract.PublishSeparation` requires two-person publish (`controlplane.BasePublishSeparation` for all or listed tenants, or `charter.PublishSeparation` from Charter separation-of-duties constraints), `publish` is refused unless the agent's latest review is approved, unconsumed, and for the candidate digest, no draft comment is open, and the publisher is no author, save the requester under the `sod_exception_id` they named while the separation still admits it. A publish consumes the review; a newer request or a rejection withdraws an earlier approval. `GET` reports `kind`, `required`, the review's `status` (`R` requested, `A` approved, `X` rejected, `S` superseded), `stale` when the draft changed since the request, and the open comments.
- `publish-review` with `restore_version` asks a second person to approve restoring that published version (at most 80 characters) over the release active now, its `base_version`. Its only author is the requester; a request supersedes only open restore reviews. Approval is `409` when the version no longer has the reviewed digest or another release became active. Where `contract.PublishSeparation` reviews restores (`BasePublishSeparation.Restores`, or `charter.PublishSeparation.Restore`), `restore` is refused (`409`) unless the agent's latest restore review is approved, unconsumed, for that version and digest, and over the active release; the restorer is not the requester, save under an exception `sod_exception_id` names. Open draft comments do not block a restore, and scheduled activations are not reviewed. `GET publish-review?kind=restore` returns `active_version`, the latest restore review, and `stale` when its `base_version` is no longer active; `kind` defaults to `publish`, and another value is `400`.
- `comment` attaches a remark to the current `draft_revision`, `anchor` `D` (the draft), `P` (a prompt section: `prompt_section_id`, optional `language_code`), or `S` (a setting: `resource_kind`, `resource_id`); `comments` lists at most 500, newest first, optionally by `status` `O` (open) or `R` (resolved).
- `approval-routing` returns the agent's effective `approval_routing` routes in precedence order, each with the widest `scope_id` declaring it and `inherited`; `coverage` lists every approval the draft can ask for (`tool_id`, `source`, `risk_tier`) with the `route_id` serving it, absent when none does; `resolver_composed`; and `problems`, what publication would refuse. As a publish guard, `StudioApprovalRouting` refuses a publish, restore, or scheduled activation with `400` on field `approval_routing` when an ask has no route, a route is unreachable, or the product's `contract.ApproverResolver` does not know a role or position; a release that can ask with no resolver composed is `503`. - `export` returns the agent's active release as a Charter AgentDefinition document: the governance members from the frozen governance section, `derivedFrom`, and extensions `scout:definition`, `scout:agent` (format `scout.agent.v1`: type, models, extension, the agent's own bindings, guardrails, and frozen settings), and `scout:digest` over the rest. ## Conversation

`handler.ConversationHandler` mounts under `BasePath` (default `/api/conversation/`) over a composed `contract.DataPlane`. Its `CallerResolver` maps the session to the tenant context and the person a turn acts for; `handler.SessionCaller` takes the session's partner and user.

| Method | Path | Body or query | Result |
|---|---|---|---|
| `POST` | `turn` | `{request_id, conversation_id, agent_type, agent_name?, release?, release_reason?, work_ref?, input}` | `202 {request_id}` |
| `GET` | `turn/stream?request_id=&cursor=` | — | SSE frames from `cursor` |
| `POST` | `turn/cancel` | `{request_id, reason?}` | `202 {request_id}` |
| `GET` | `agents?agent_type=` | — | `[{agent_name, display_name, is_default, release}]` |
| `POST` | `turn/feedback` | `{request_id, rating, reason?}` | `202 {request_id}` |

`agent_type` is the type alias. Without `agent_name` the conversation's agent serves the turn, and a new conversation takes the alias target; with it, that agent must be of the alias's type, and no other agent is substituted on failure. The data plane resolves the serving agent's principal, refuses an agent that does not admit work (disabled, suspended, draining, archived, retired), and authorizes the person for `AGENT_CONVERSATION` `USE` at `agent:<id>`. `release` pins a new conversation to one immutable, unquarantined release instead of the traffic policy; it needs `PIN_RELEASE` and `release_reason`, and a conversation already on another release refuses it. `work_ref` is the product's opaque reference to the work the turn serves, carried onto usage and decision records. `agent_type`, `agent_name`, and `release` are at most 80 bytes and `release_reason` and `work_ref` at most 200. The resolved session must name a person. A new turn beyond the `turns_per_minute` limit of the conversation's release is `429` with `Retry-After`; a replayed `request_id` is never refused. A turn the release budget cannot hold is `429`: for a `day` or `month` budget spent by earlier use, `Retry-After` is the time until the period ends, while a `rolling` budget or a turn larger than the whole period ceiling carries none. A budget the ledger cannot enforce (`domain.BudgetUnenforceableError`, the limits report's `problem`) fails the turn closed. A turn suspended for approval or held ends its delivery with a `final` frame carrying an `error_code` whose last event is `approval_pending` or `held` (error code `held`); the resumed or released turn continues the stream at that frame's sequence. `agents` lists the deployed agents of a type the person may use, the default first. `turn/feedback` rates the signed-in person's own completed turn from 1 to 5; a second rating replaces the first, and reports never identify the giver. It needs `ConversationHandler.Feedback`, a `dataplane.TurnFeedback`.

## Approval

`handler.ApprovalHandler` serves the approval desk, `contract.ApprovalDesk`, implemented by `approval.Resumer`.

| Method | Path | Body | Result |
|---|---|---|---|
| `GET` | `/api/approval/pending` | — | the requests the signed-in person may decide now, soonest deadline first |
| `POST` | `/api/approval/resolve` | `{request_id, execution_step_id, verdict, proposed_digest, reason?, revised_arguments?}` | the decided request |
| `POST` | `/api/approval/link` | `{token, tenant_id, request_id, execution_step_id, verdict, reason?}` | the decided request; no session |

A pending request carries `output_class` (`A` advice, `D` draft, `R` approval request, or `C` completed action), `rule_source` (`autonomy`, `policy`, or `guardrail`), the `rule_id` within it, `route_step`, and, when the release's `approval_routing` routed it, `route_id` and `approver_reference {kind, ref}`. Nobody may decide a routed request that has no approver yet (`403`) until escalation fills it, and `resolve` on a request reassigned since it was read is `409`.

A verdict is an approval status code: `A` (approved), `X` (rejected), or `E` (edited). `Resolve` authorizes the decider, records the verdict once against the exact `proposed_digest`, requeues an approved turn's delivery, and fails a rejected one. `E` applies to a tool-call proposal and carries `revised_arguments`, a JSON object of at most 64 KiB by default, which no other verdict may carry. The arguments are archived through `contract.EvidenceArchive`, the original call never runs, and the requeued turn runs the revised call in its place through the full tool governance; one that needs approval again parks as a new request whose `revises_step_id` names the edited one. A call takes at most 8 revisions. Repeating the same edit replays; a different edit already recorded is `409`.

A decision link is a single-use keel `actiontoken` bound to one person, one request, one verdict (`A` or `X`, never an edit), and the proposal digest. The product's notifier delivers it: `Resumer.MintLink` authorizes the person, refuses a request riskier than `Resumer.LinkMaxRisk` (empty refuses every link), and lapses at the request's deadline. Redemption authorizes the person again and decides under their identity. A spent, expired, or mismatched link, or any refusal before the token is verified, is `404`; a valid link whose person may no longer decide, or whose decision is already settled differently, is `403`.

## Errors

| Domain condition | HTTP status |
|---|---:|
| malformed request or `domain.ErrValidation` | `400` |
| unauthenticated session, `domain.ErrUnauthorized`, or `domain.ErrPrincipalUnknown` | `401` |
| missing partner context, `domain.ErrForbidden`, or a widening or loosening change / `domain.ErrAuthorityExceeded` | `403` |
| missing agent, release, conversation, or link / `domain.ErrNotFound` | `404` |
| stale revision, archived agent, disabled agent / `domain.ErrConflict` or `domain.ErrRevisionConflict`; a layer under a sealed one / `domain.ErrSealed`; a moved turn fence or a held turn / `domain.ErrFenceLost` or `domain.ErrTurnHeld` (Studio routes) | `409` |
| an agent's own execution limit stopped the work / `domain.ErrExecutionLimit` (Studio and approval routes; the detail is fixed) | `422` |
| quota, turn rate, or budget limit / `domain.ErrRateLimited` or `domain.ErrBudgetExceeded` | `429`, with `Retry-After` when the error carries one, through any wrapping |
| no executable release / `domain.ErrNotReady` or `domain.ErrCircuitOpen` | `503` |
| unclassified failure | `500` |

Studio and approval request bodies decode strictly and are capped at keel's `MaxRequestSize`: an unknown member, trailing data, or an oversized body is `400`. Errors use keel's `application/problem+json` envelope. A field-validation failure serializes `api.ValidationProblem` — a message and `fields` of `{field, message}` — into the problem's `detail`. A `5xx` detail is replaced by a request ID; the cause is logged.

## Compatibility boundary

The promise covers the routes above. Product capability catalogs, provisioning, prompt seed content, and task execution remain application contracts.
